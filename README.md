# DigiCanji v2.0.5

手書き認識を利用した漢字学習アプリと、配布用クイズHTMLを生成するエディターです。

## v2.0.5 「々」などUnicode文字種の取りこぼし修正

- エディターの解答文字チェックを、BMP内の固定コードポイント範囲から Unicode `Script=Han` / `Script=Hiragana` ベースへ変更しました。これにより `々`・`〇`・`〻` のように一般的な漢字範囲外へ配置された表意文字系記号や、補助漢字面の漢字も、書き問題の解答へ含められます。
- `〆`、`〼`、縦組み用かな反復記号 `〱〜〵`、カタカナ反復記号 `ヽ・ヾ`、`ヵ・ヶ`、長音符 `ー` を、日本語表記に必要な例外文字として限定的に許可しました。句読点など任意の記号は解答文字として許可しません。
- プレイヤー側の候補判定も同じ文字種へそろえ、`〆` など Unicode の Han / Kana スクリプト外にある対応済み記号が単独候補でも除外されないようにしました。標準画数データがない例外記号は、従来の「画数不明の漢字」と同様に、外部認識候補を安全検査したうえで扱います。
- `々` は既存の3画データと Han 候補経路、`〇` は既存の1画データと Han 候補経路をそのまま使用します。認識順位・字体閾値・候補安定化の重みは v2.0.4 から変更していないため、93点評価へ復元した通常漢字の認識基準を維持します。
- エディター内蔵プレイヤーは `kanji_sample.html` と再同期し、追加の自己試験で特殊文字の候補通過・Unicode分類を回帰確認します。
- 配布ZIP直下のフォルダー名は `DigiCanji_v2.0.5` です。今回は新チャット継続用の `DIGICANJI_WORK_HANDOFF_v2.0.5.md` も同梱します。

## v2.0.4 認識回帰の修正

- v2.0.3で追加した「正解文字を候補へ再注入する全漢字共通の回復経路」を撤回しました。この経路が外部認識候補と正解文字を競合させ、「受・残」を含む広範な正しい筆跡で候補順位を不安定にしたことが、78点評価への低下の原因でした。
- 認識順位、候補選択、字体判定は、過去最高の93点評価を得たv2.0.2と同一内容へ復元しました。今回、新しい文字別規則や閾値変更は加えていません。
- バックグラウンド認識、「？」表示、確定・回答時の認識完了待ち、認識枠を隠さない比較可能な解説表示など、v2系のUI・操作改善は維持しています。
- 配布ZIP直下のフォルダー名は `DigiCanji_v2.0.4` です。展開後の版を取り違えにくい構成にしました。

## v2.0.3 正解候補漏れの一般回復（v2.0.4で撤回）

- 「自」「合」だけに設けていた文字固有の救済表と専用骨格関数を廃止し、書き問題の全漢字に共通する回復経路へ置き換えました。外部認識器の候補から正解文字が落ちた場合でも、その文字を端末内字体と照合して候補へ戻せます。
- 回復は、正解文字との一致、標準画数、既存の部首・対照構造検査、全体字形・縦横比補正・端点除去を含む複数変形の支持がそろった場合に限ります。正解文字を無条件に確定せず、誤画数や明確な構造不一致は従来どおり拒否します。
- 回復候補では活字体由来の減点だけを上限付きで緩め、「正しい入力が候補なしや別字になる」損失を優先して抑えました。既存の外部候補順位、阪／阨などの対照規則、小書きかな、バックグラウンド認識、確定待ち、比較可能な解説表示は維持しています。
- 文字別データを増やさず、既存の字体キャッシュと筆跡変形を再利用します。追加通信は行わず、処理量と配布サイズの増加を小さく保っています。

## v2.0.0 認識安定化・バックグラウンド認識・回答確定

- 初期プロトタイプの長所だった外部認識候補順を維持しながら、僅差候補は同じ筆跡で1回安定確認します。端末フォントの接触・被覆率だけで外部候補を脱落させず、画数・部品位相・筆順・中心骨格が一致する候補を残します。

- 「進む」をスリム化して「確定」を追加しました。確定した問題はその場で採点・ロックし、単円または三角の控えめな正誤演出と解説を重ねて表示します。任意のタップで次の未確定問題へ進み、最後尾では「回答」と表示します。
- 問題データ800問、エディター内プレイヤーとの完全一致、内蔵認識自己試験107ケース、確定・復習ロック・最終問題からの未確定復帰を自動確認しています。

## v1.24.1 「阪」と「阨」の右側部品判定

- 「阪」の筆跡が、同じこざとへんを持つ表外字「阨」と認識される経路を追加調査しました。「阨」は画数辞書に未登録だったため、単漢字の画数不明候補として残り、v1.24.0の「岐・坂・飯」向け回復規則も適用されていませんでした。

- 「阨」の標準画数7画も補助辞書へ登録しました。これにより、実在する「阨」の入力を一律に「阪」へ置換せず、画数と右側部品をそれぞれ検査できます。問題の正解文字は判定に使用していません。

## v1.24.0 微差に強い候補統合と「阪」の部品判定

- 実機画像8枚を比較し、「庫/島」「府/村」は正答が候補内に残っていても、1画の長さ・端点・接触の僅かな違いで未正規化入力の首位だけが入れ替わることを確認しました。字体画像比較は例によって「府」より「京・都」、「阪」より「岐・飯」を良く評価する場合があり、これを強めず、外部候補の安定性側を調整しました。

- 「阪」は、先頭2画が明確なこざとへんで、3画目から右側の「反」へ移る構造を確認した場合だけ、同画数の「岐・坂」や簡体字「饭」由来の候補から回復します。この構造が明確な「阪」に限り、端末フォントの阝形状との差による字体減点へ上限を設けます。画数、右側部品、外部候補順位は通常どおり検査し、問題の正解文字は判定に使用しません。

## v1.5.0から継続する回答方式

### 全問題を1枠1文字へ統一

書き問題だけでなく、読み問題も1枠1文字で認識します。通常の問題では文字列全体を一度に認識しないため、縦書きで起きていた文字順の入れ替わり、文字数の増減、濁点の所属先の誤判定を回避できます。

### 常に10枠を表示

正答の文字数に関係なく、すべての問題で10枠を用意します。正答長から送り仮名を推測できません。未入力の末尾枠は採点時に無視し、余分な文字を入力した場合は不正解になります。

### 正方形のスクロール式認識欄

- 横書きレイアウト：正方形枠を横1列に並べ、横スクロール
- 縦書きレイアウト：正方形枠を縦1列に並べ、縦スクロール
- 枠のクリック・タップ、矢印キーで選択
- 選択した枠は自動的に表示範囲へ移動

## 認識処理

- 読み問題では、カタカナ候補をひらがなへ正規化します。
- 読み問題では、1文字のひらがな候補だけを採用します。
- 書き問題では、漢字・かなを含む1文字候補を従来どおり画数・構造・認識器間一致で評価します。
- 通常認識が確実な場合は外部再認識を行わず、通信と処理を抑えます。

## 問題データ

```text
前部,問部,後部,解答,解説
```

- 最大1000問
- 1回の出題は最大10問、重複なし
- 正答率が低い問題と未出題問題を優先する重み付きランダム
- 問部と解答が同一、または解答にひらがな・漢字以外を含む場合はエラー
